## Optimization

Once the IR is generated, we then perform optimization on the IR. In the previous deliverable, there was only one
optimization performed with was dead code elimination. As a part of this deliverable, there are:

1. Dead code elimination (from before)
2. Constant folding
3. Copy propagation
4. Constant propagation
5. Logic gate elimination

The relevant methods are implemented in the files under the `edu.columbia.circuitc.opt` package. These optimizations
are implemented as a pass over the IR using the `IRVisitor` interface. 

### Dead Code Elimination

See: DeadCodeElimination.kt for the implementation

For dead code elimination, we need to find any input pins or tunnels which are never used -- and therefore can be
eliminated. Using a pass over the IR, we keep track of usage counts of these constructs and if any have no usage, then
they can be safely eliminated.

Since dead code elimination can lead to additional dead code, we loop through and perform this pass as many times as
needed until the IR does not change, after which it is returned back and used in the SIM code generation phase.

### Constant Folding

See: ConstantFolding.kt for the implementation

For constant folding, we eliminate any logic gate that has *both* inputs which are constants -- as that can be evaluated
statically by the compiler and just replace them with a single constant value. 

### Copy Propagation

See: CopyPropagation.kt for the implementation

For copy propagation, we check whether an identifier used in an expression is a tunnel whose input value is either
another tunnel or an input pin and so can just be replaced with that construct directly.

```
Original:
     bits<4> a = <...>
     bits<4> b = a;
     bits<4> c = b and d;
 
 Optimized:
     bits<4> a = <...>
     bits<4> b = a;
     bits<4> c = a and d;
```

### Constant Propagation

See: CopyPropagation.kt for the implementation (this optimization is implemented in the same file as copy propagation)

For constant propagation, we check whether an identifier used in an expression is a tunnel whose input value
is a constant and so can just be replaced with that constant directly.

```
Original:
    bits<4> a = 3;
    bits<4> b = a;

Optimized:
    bits<4> a = 3;
    bits<4> b = 3;
```

### Logic Gate Elimination

See: LogicGateElimination.kt for the implementation

This optimization is similar in concept to constant folding; however, it operates on gates that have one non-constant
value. Certain values of a single constant input to a gate make it such that they alone dictate the output value, so it
doesn't matter what the other (non-constant) value is.

For example, x OR 1111 (assuming x is 4 bits) will just be 1111. Therefore, we don't need to keep this OR gate and can
just simplify the expression to 1111. Similarly, x AND 0 will be just be 0. 

There's also another interesting scenario which leads to gate simplification even though the output remains non-constant.

For example, x AND 1111 (assuming x is 4 bits) will just be x. Similarly, x OR 0 will just be x. Again, we don't need to
keep the AND or OR gates; however, the result is not constant, as 'x' is not a constant.

## Installation Steps and Running
To build and run the sample programs (described below), there is a provided Dockerfile which will set up a container with JDK 17 installed and run the execute.sh script which runs all the sample programs.

Assumption: docker is installed

```shell
docker build -t circuitcc .
docker run circuitcc
```

This will compile each of the sample programs and output the SIM code generated by the compilation.

## CircuitSim

The generated output (.sim) can be simulated using the CircuitSim software, which can be downloaded from:
https://www.roiatalla.com/public/CircuitSim/Jar/.

To run the software, `java -jar CircuitSim1.9.2b.jar`, which will launch the UI. From there, it's possible to load in
the .sim file and play around with the circuit, which is demonstrated in the demo video above.

For each of the sample programs, there is a screenshot of what each generated circuit looks like in the CircuitSim
software in the README below.

variable `tmp` which is assigned the value of `a` but otherwise never used. Therefore, this variable is dead and can

which are assigned constant values. We can just propagate the constant values to that AND gate (rather than the
tunnels) and eliminate the tunnels altogether. In addition, constant folding is run, which computes the overall value
and eliminates the AND gate as well.

```
propagating ConstantValue(bitWidth=4, value=5)
propagating ConstantValue(bitWidth=4, value=3)
propagating ConstantValue(bitWidth=4, value=5)
propagating ConstantValue(bitWidth=4, value=3)
Folding 5 and 3 into 1
```
